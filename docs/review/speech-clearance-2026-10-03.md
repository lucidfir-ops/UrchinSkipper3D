The fix is confined to default career speech placement.

`src/three/speech-footprints.js` caches the boat model's local mesh envelope, including rendered height, cabin and port ladder, once per model. Current boat transforms and the actual orthographic camera project its eight corners while a career notice is active. A conservative local pad covers small child animation. A replacement model receives a new cached envelope. Recovered deck sacks have a separate load-local envelope that includes actual body and knot instance transforms. It refreshes when the load key, instance pool, live count, visibility or matrix version changes; unchanged loads do not traverse instances every frame. This covers tall stacks above the fixed rig and pool growth without rebuilding the vessel. Both physically visible surfaced diver groups contribute their rendered body, float and lift-line bounds; an already-visible selection ring is also protected. Hidden or submerged diver positions do not contribute. The renderer provides these footprints without changing authoritative simulation state, boat following or zoom.

`src/speech-layout.js` chooses a viewport-contained rectangle using the notice's measured wrapped height, including its five-pixel tail. The whole notice needs an eight-pixel gap from protected world footprints and visible labelled keyboard/touch actions and sticks. Placement initially reserves another four pixels around moving world geometry, while subsequent frames require the mandatory eight pixels; this prevents tiny boat movements from restarting the search every frame. A tight view that cannot fit the extra buffer retries the mandatory gap. Instrument panels are secondary avoidance areas. The preferred position and width remain favored where clear; narrower wrapping supplies alternatives for close views, down to 90 pixels with safe word wrapping and the unchanged 12-pixel font. A chosen position stays stable while the protected geometry remains clear. Placement is discarded when speech hides, including menu visits, so a later identical notice considers the current layout. If no clear rectangle exists, the solver returns an explicit `clear: false` best fit and leaves the notice visible; this is a fallback, not an assertion of universal clearance.

The first production sweep passed all 1,152 fixed-vessel world-clearance cases, but independent review caught two close phone catamaran screenshots where the resulting narrow notice covered Ahead/Centre rudder. That rejection remains in `test-results/vessel-speech-2026-10-03/hud-context/`. The revised solver makes labelled controls hard constraints and allows concise routine pickup text only when full wording would impose substantially greater obstruction. `src/hud-view.js` supplies the actual recovery cause: for example, “Ada · Float to port,” “Milo · Come closer” or “Ada · Slow down.” A first name is used only when unique among the two divers. Injured crew, active operations/pauses, explicit notices, unknown causes and nonroutine surfacing warnings retain full wording. Essential identity and pickup cause remain in the bubble even if crew cards are hidden. A changed recovery cause has its own semantic key; repeated identical telemetry still cannot extend the notice's lifetime.

A later production review found that a clear but very narrow full notice could take nine or ten lines, with midword wrapping, despite lasting only 2.6 seconds. Ordinary two-to-four-line full notices remain preferred; unique warnings never acquire an abbreviated alternative. The captured compact loaded-outboard and close portrait catamaran rectangles are regression inputs.

The compact active-speech sample was nevertheless marginal: the first run fell below 40 FPS, and the same-build rerun recorded 40.83 FPS. That prompted the performance change rather than dismissal of the first failure.

A pure Node timing probe used the recorded compact catamaran rectangles, all ten measured full-text sizes, twenty full/concise variants, 24 critical obstacles and six instrument/crew rectangles. Before optimization, the placement search took a median 5.15 ms and p95 8.73 ms; a world edge advancing only 0.05 pixels per frame triggered 119 new searches in 120 frames, costing 626.6 ms. Exact-result pruning reduced the same static search to median 1.29 ms and p95 1.96 ms while selecting the same rectangle and wording. With the four-pixel world buffer, the drift probe required one new search after initial placement, about 3.45 ms total. Candidates whose minimum possible score cannot improve a clear result are skipped; collisions stop early, and an unobstructed zero-cost result ends the search. Unchanged speech no longer replaces its text node each frame. These are CPU microbenchmarks and a focused regression, not final browser or GPU performance claims.
